1. Basic Device Configuration Review Module 1

1.1 Switch Boot Sequence

  1. Switch loads POST (Power-On Self Test) from ROM
  2. Boot loader software is loaded from ROM
  3. Boot loader initializes CPU and flash memory
  4. Boot loader locates and loads IOS image from flash
  5. IOS loads startup-config from NVRAM into RAM as running-config
  6. If no startup-config exists → Setup Mode launches

1.3 Duplex & Speed Configuration

S1(config)# interface fastethernet 0/1
S1(config-if)# duplex full          ! full / half / auto
S1(config-if)# speed 100            ! 10 / 100 / 1000 / auto
S1(config-if)# description Link to R1
S1(config-if)# no shutdown

! Best practice — always set speed/duplex on uplinks
! Leave access ports on auto for end devices
! Duplex mismatch = slow speeds, late collisions, errors
Duplex mismatch is one of the most common causes of poor performance on a switch port. One side set to full, other set to half = both think they're right, collisions happen constantly, throughput tanks. Always match duplex on both ends, or set both to auto.

2. Switching Concepts Module 2

2.1 Frame Forwarding Methods

MethodHow It WorksLatencyError Checking
Store-and-ForwardReceives entire frame, checks FCS, then forwardsHigher✅ Full CRC check — drops corrupt frames
Cut-ThroughStarts forwarding after reading destination MAC (first 6 bytes)Very Low❌ No error check — forwards corrupt frames
Fragment-FreeReads first 64 bytes (collision fragment size) then forwardsLow⚠️ Partial — catches most collision fragments

2.2 Switch MAC Address Table

  • Switch builds MAC table by learning source MACs from incoming frames
  • Switch forwards frames by looking up destination MAC in the table
  • If destination MAC not found → switch floods frame out all ports except source (unknown unicast flooding)
  • If destination MAC found → switch forwards only out the matching port (unicast)
  • If destination is broadcast/multicast → switch floods out all ports except source
  • MAC entries have an aging timer — default 300 seconds (5 minutes) of inactivity = removed
! View the MAC address table
S1# show mac address-table
S1# show mac address-table dynamic           ! Only learned entries
S1# show mac address-table address aaaa.bbbb.cccc  ! Specific MAC
S1# show mac address-table interface fa0/1   ! MACs on specific port

! Clear the MAC table (forces relearning)
S1# clear mac address-table dynamic

! Add a static MAC entry (permanent — won't age out)
S1(config)# mac address-table static aaaa.bbbb.cccc vlan 1 interface fa0/1

3. VLANs — Virtual Local Area Networks Module 3 Lab Heavy

3.1 VLAN Concepts

  • VLANs create logical broadcast domains within a physical switch
  • Traffic in one VLAN cannot reach another VLAN without a Layer 3 device (router or L3 switch)
  • Benefits: Security, traffic reduction, flexibility, easier management
  • VLAN 1 = Default VLAN — all ports start here — change this for security
  • VLANs 1002–1005 = Legacy Token Ring/FDDI — reserved, cannot be deleted
  • Normal range VLANs: 1–1005 | Extended range: 1006–4094

3.2 Port Types

Trunk PortMultiple VLANsYes — 802.1Q tagsOther switches, routers, servers

3.5 802.1Q Tagging

  • IEEE 802.1Q inserts a 4-byte tag into the Ethernet frame between Source MAC and Type fields
  • Tag contains: TPID (0x8100), PCP (priority), DEI (drop eligible), VLAN ID (12 bits = 4096 VLANs)
  • Native VLAN frames are sent untagged on a trunk — both sides must agree on which VLAN is native
  • Native VLAN mismatch = CDP warning + possible VLAN hopping vulnerability
Native VLAN security: Change the native VLAN from VLAN 1 to an unused VLAN (like 99) that has no devices. VLAN 1 is the default and attackers know it. Also tag the native VLAN explicitly: vlan dot1q tag native under global config. This prevents double-tagging VLAN hopping attacks.

5. Spanning Tree Protocol (STP) Module 5

5.1 Why STP Exists

Redundant switch links are great for uptime — but without STP, they create broadcast storms. A broadcast frame enters the loop, gets duplicated endlessly, consumes all bandwidth, and crashes the network within seconds. STP prevents this by blocking redundant paths while keeping them available for failover.

5.2 STP Port States

StateSends BPDUs?Learns MACs?Forwards Traffic?Duration
BlockingReceives onlyNoNoUp to 20 sec (Max Age)
ListeningYesNoNo15 sec (Forward Delay)
LearningYesYesNo15 sec (Forward Delay)
ForwardingYesYes✅ YesNormal operation
DisabledNoNoNoAdmin shutdown

⏱️ STP convergence time: Classic 802.1D takes up to 50 seconds to converge (20 max age + 15 listening + 15 learning). RSTP converges in ~1–2 seconds. Always use RSTP!

5.3 STP Election Process

  1. Elect Root Bridge — Switch with lowest Bridge ID wins. Bridge ID = Priority (default 32768) + VLAN ID + MAC address. Tie on priority → lowest MAC wins.
  2. Elect Root Ports — Each non-root switch picks one Root Port — the port with the lowest path cost to the Root Bridge.
  3. Elect Designated Ports — One Designated Port per segment — the port with the lowest path cost to Root Bridge on that segment.
  4. Block remaining ports — All non-Root, non-Designated ports go into Blocking state.

5.4 STP Port Cost Values

Link SpeedSTP Cost (802.1D)RSTP Cost (802.1w)
10 Mbps1002,000,000
100 Mbps19200,000
1 Gbps420,000
10 Gbps22,000

5.5 STP Configuration & RSTP

! ===== CHECK CURRENT STP =====
S1# show spanning-tree                       ! Full STP info all VLANs
S1# show spanning-tree vlan 10               ! STP for specific VLAN
S1# show spanning-tree summary               ! Quick summary

! ===== SET ROOT BRIDGE =====
! Method 1 — Set priority manually (must be multiple of 4096)
S1(config)# spanning-tree vlan 10 priority 4096      ! Lower = more likely to win
S1(config)# spanning-tree vlan 20 priority 8192

! Method 2 — Use macro (sets primary or secondary automatically)
S1(config)# spanning-tree vlan 10 root primary       ! Sets priority to 24576
S1(config)# spanning-tree vlan 20 root secondary     ! Sets priority to 28672

! ===== CONFIGURE RSTP (Rapid Spanning Tree) =====
S1(config)# spanning-tree mode rapid-pvst            ! Enable RPVST+ (per-VLAN RSTP)

! ===== PORTFAST — for access ports connected to end devices =====
! Skips listening/learning — goes straight to forwarding
S1(config)# interface fa0/6
S1(config-if)# spanning-tree portfast               ! On individual port

S1(config)# spanning-tree portfast default          ! Enable on ALL access ports globally

! ===== BPDU GUARD — protect PortFast ports =====
! Shuts down port if BPDU received (prevents rogue switches)
S1(config-if)# spanning-tree bpduguard enable       ! On individual port
S1(config)# spanning-tree portfast bpduguard default ! On all PortFast ports

! ===== MODIFY PORT COST & PRIORITY =====
S1(config)# interface gi0/1
S1(config-if)# spanning-tree vlan 10 cost 1         ! Lower cost = preferred path
S1(config-if)# spanning-tree vlan 10 port-priority 64  ! Lower = more likely Root Port
PortFast + BPDU Guard together: Always configure both on access ports. PortFast skips the 30-second delay so PCs get connectivity immediately. BPDU Guard protects against someone plugging a rogue switch into that port — the moment a BPDU arrives, the port goes into err-disabled state. To recover: shutdown then no shutdown or configure errdisable recovery cause bpduguard.

6. EtherChannel Module 6 Lab Heavy

6.1 EtherChannel Concepts

  • Bundles 2–8 physical links into one logical link
  • STP sees it as a single link — no blocking of bundled ports
  • Load balancing across all active links
  • If one link fails, traffic redistributes to remaining links automatically
  • All links in bundle must have identical: speed, duplex, VLAN config, trunk/access mode

7.2 DHCP Relay Agent (ip helper-address)

! Problem: DHCP uses broadcasts — broadcasts don't cross routers
! Solution: ip helper-address forwards DHCP broadcasts as unicast to DHCP server

! Configured on the router interface CLOSEST to the client (not the server)
R1(config)# interface gi0/0                 ! Interface facing VLAN 10 clients
R1(config-if)# ip helper-address 10.1.1.5  ! IP of DHCP server on another subnet

! If using ROAS — configure on each subinterface
R1(config)# interface gi0/0.10
R1(config-subif)# ip helper-address 10.1.1.5

R1(config)# interface gi0/0.20
R1(config-subif)# ip helper-address 10.1.1.5

! Verification — confirm helper is set
R1# show ip interface gi0/0 | include Helper
ip helper-address forwards more than just DHCP: By default it forwards 8 UDP broadcast services: DHCP (67/68), TFTP (69), DNS (53), Time (37), NetBIOS name service (137), NetBIOS datagram (138), TACACS (49), and BootP (67/68). If you only want DHCP forwarding, you can restrict it, but for the CCNA exam just know it primarily solves the DHCP-across-router problem.

9. FHRP — First Hop Redundancy Protocols Module 9

9.1 The Problem FHRP Solves

End devices are configured with a single default gateway IP. If that router fails, the device has no gateway and loses connectivity — even if another router is available. FHRPs create a virtual IP (VIP) and virtual MAC shared between two routers. Clients point to the VIP. If the active router fails, the standby takes over the VIP automatically.

9.2 FHRP Comparison

ProtocolVendorStandardTerm for ActiveTerm for Standby
HSRP v1/v2CiscoProprietaryActiveStandby
VRRPOpenRFC 5798MasterBackup
GLBPCiscoProprietaryAVG (Active Virtual Gateway)AVF (Active Virtual Forwarder)

9.3 HSRP Configuration Lab Heavy

! ===== HSRP on R1 (Active — higher priority wins) =====
R1(config)# interface gi0/0
R1(config-if)# ip address 192.168.1.2 255.255.255.0      ! Real IP
R1(config-if)# standby version 2                          ! Use HSRPv2
R1(config-if)# standby 1 ip 192.168.1.1                  ! Virtual IP (group 1)
R1(config-if)# standby 1 priority 150                     ! Higher priority = Active (default=100)
R1(config-if)# standby 1 preempt                          ! Take back Active role when restored
R1(config-if)# standby 1 track 1 decrement 60            ! If tracked interface fails, drop priority by 60

! Track the WAN interface — if it goes down, drop priority so R2 takes over
R1(config)# track 1 interface gi0/1 line-protocol

! ===== HSRP on R2 (Standby) =====
R2(config)# interface gi0/0
R2(config-if)# ip address 192.168.1.3 255.255.255.0      ! Real IP — different from R1!
R2(config-if)# standby version 2
R2(config-if)# standby 1 ip 192.168.1.1                  ! SAME virtual IP as R1
R2(config-if)# standby 1 priority 100                     ! Lower priority = Standby
R2(config-if)# standby 1 preempt

! ===== VERIFICATION =====
R1# show standby                            ! Full HSRP status
R1# show standby brief                      ! Summary — shows Active/Standby state
R1# show standby gi0/0                     ! Specific interface
HSRP virtual MAC address: HSRPv1 uses 0000.0c07.acXX (XX = group number in hex). HSRPv2 uses 0000.0c9f.fXXX. Clients ARP for the virtual IP and get the virtual MAC back. When failover happens, the new active router sends a gratuitous ARP to update switches' MAC tables — traffic rerouting happens in milliseconds.

11. Switch Security Configuration Module 11 Lab Heavy

11.1 Port Security

! Port Security restricts which MACs can use a port

! ===== BASIC PORT SECURITY =====
S1(config)# interface fa0/6
S1(config-if)# switchport mode access             ! Must be access port
S1(config-if)# switchport port-security           ! Enable port security

! Set maximum allowed MACs (default = 1)
S1(config-if)# switchport port-security maximum 2

! Manually define allowed MAC
S1(config-if)# switchport port-security mac-address aaaa.bbbb.cccc

! Sticky learning — dynamically learn and save MACs to running-config
S1(config-if)# switchport port-security mac-address sticky

! ===== VIOLATION MODES =====
S1(config-if)# switchport port-security violation shutdown   ! Default — err-disables port, sends SNMP trap, logs
S1(config-if)# switchport port-security violation restrict   ! Drops violating frames, increments counter, logs
S1(config-if)# switchport port-security violation protect    ! Silently drops violating frames — no log

! ===== RECOVER FROM ERR-DISABLED =====
S1(config)# interface fa0/6
S1(config-if)# shutdown
S1(config-if)# no shutdown

! Or configure automatic recovery
S1(config)# errdisable recovery cause psecure-violation
S1(config)# errdisable recovery interval 300     ! Recover after 300 seconds

! ===== VERIFICATION =====
S1# show port-security                           ! Summary of all port-security
S1# show port-security interface fa0/6           ! Detail for one port
S1# show port-security address                   ! All secure MAC addresses

11.4 Additional Security Best Practices

! Disable unused ports — put in unused VLAN, shutdown
S1(config)# interface range fa0/13 - 24

13. WLAN Configuration Module 13 Lab Heavy

13.1 Configuring a Home Wireless Router

  • SSID: Network name — keep it non-identifying (don't use your address)
  • Channel: For 2.4GHz use 1, 6, or 11 (non-overlapping). For 5GHz channels don't overlap.
  • Security: WPA2-Personal minimum — WPA3 if devices support it
  • Passphrase: Long and random — at least 12 characters
  • Guest network: Separate SSID/VLAN for visitors — isolated from main LAN

13.2 WLC Basic Configuration Steps

  1. Connect to WLC via console or initial web setup wizard
  2. Set management IP, subnet mask, default gateway
  3. Configure WLAN (SSID, security profile, VLAN mapping)
  4. Configure RADIUS server for WPA2-Enterprise (if used)
  5. Deploy APs — they discover WLC via DHCP option 43 or DNS
  6. APs join WLC and download config automatically

14. Routing Concepts Module 14

14.1 Router Functions

  • Path determination: Uses routing table to find best path to destination
  • Packet forwarding: De-encapsulate frame, make routing decision, re-encapsulate in new frame, forward
  • Each router hop decrements TTL by 1 — packet dropped if TTL reaches 0
  • Router never forwards broadcasts — segments broadcast domains

15.1 Types of Static Routes

TypePurposeExample
Standard StaticRoute to specific networkip route 192.168.2.0 255.255.255.0 10.0.0.2
Default StaticCatch-all — all unmatched trafficip route 0.0.0.0 0.0.0.0 10.0.0.1

15.2 Static Route Configuration

! Syntax: ip route [network] [mask] [next-hop IP | exit-interface] [AD]

! ===== NEXT-HOP STATIC ROUTE (recommended for Ethernet) =====
R1(config)# ip route 192.168.2.0 255.255.255.0 10.0.0.2

! ===== EXIT INTERFACE STATIC ROUTE (use for serial/point-to-point) =====
R1(config)# ip route 192.168.2.0 255.255.255.0 serial 0/0/0

! ===== FULLY SPECIFIED (both next-hop AND exit interface) =====
R1(config)# ip route 192.168.2.0 255.255.255.0 gi0/1 10.0.0.2

! ===== DEFAULT STATIC ROUTE =====
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1    ! Via next-hop
R1(config)# ip route 0.0.0.0 0.0.0.0 gi0/1        ! Via interface

! ===== FLOATING STATIC (backup route) =====
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1      ! Primary (AD=1)
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.5 5    ! Floating backup (AD=5)

! ===== IPv6 STATIC ROUTES =====
R1(config)# ipv6 route 2001:DB8:ACAD:2::/64 2001:DB8:ACAD:1::2  ! Next-hop
R1(config)# ipv6 route ::/0 2001:DB8:ACAD:1::2                   ! Default route

! ===== VERIFICATION =====
R1# show ip route static                    ! Only static routes
R1# show ip route 192.168.2.0              ! Details about specific route
R1# show running-config | include ip route  ! All static routes in config

The golden troubleshooting rule for static routes: For every path you want traffic to flow, you need a route in BOTH directions. If PC-A can reach PC-B but PC-B can't reach PC-A, there's a missing return route somewhere in the middle. Draw out the topology, trace the packet both ways, and add whatever route is missing. Asymmetric routing causes more headaches than almost anything else.
