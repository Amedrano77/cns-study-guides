1. OSI & TCP/IP Models

1.1 The OSI Model — All 7 Layers

💡 Memory trick: "Please Do Not Throw Sausage Pizza Away" — Physical, Data Link, Network, Transport, Session, Presentation, Application

#LayerFunctionProtocols / Devices
7ApplicationUser-facing servicesHTTP, FTP, DNS, SMTP
6PresentationEncryption, compression, formattingSSL/TLS, JPEG, ASCII
5SessionEstablish, manage, terminate sessionsNetBIOS, RPC, PPTP
4TransportEnd-to-end delivery, segmentationTCP, UDP
3NetworkLogical addressing, routingIP, ICMP, Router

1.2 TCP/IP Model (DoD Model)

TCP/IP LayerOSI EquivalentKey Protocols
ApplicationLayers 5, 6, 7HTTP, HTTPS, DNS, DHCP, FTP, SSH, SMTP
TransportLayer 4TCP (reliable), UDP (fast)
InternetLayer 3IP, ICMP, ARP
Network AccessLayers 1, 2Ethernet, Wi-Fi, MAC
TCP vs UDP: TCP is like certified mail — guaranteed delivery, ordered, slower. UDP is like shouting across a room — fast, no guarantee. Use TCP for accuracy (web, email), UDP for speed (video, VoIP, DNS).

Subnetting formula: Hosts = 2n - 2 (n = host bits). Always subtract 2 — one for network address, one for broadcast. The exam WILL test this. Practice until it's automatic.

2.4 IPv6 Basics

  • 128-bit address — written as 8 groups of 4 hex digits: 2001:0db8:85a3::8a2e:0370:7334
  • Loopback: ::1 (like 127.0.0.1 in IPv4)
  • Link-local: fe80::/10 — auto-assigned, not routable
  • Global unicast: 2000::/3 — publicly routable
  • No broadcast in IPv6 — uses multicast instead
  • No NAT needed — every device gets a public address

5. Routing & Switching

5.1 VLANs

VLANs (Virtual LANs) logically segment a network on a single physical switch.

  • Access port: connects end devices — carries one VLAN
  • Trunk port: connects switches/routers — carries multiple VLANs tagged with 802.1Q
  • Native VLAN: untagged traffic on a trunk — default VLAN 1 (change it for security!)

5.2 Routing Protocols

ProtocolTypeAlgorithmKey Detail
RIPDistance VectorHop count (max 15)Old, slow convergence — rarely used
OSPFLink StateDijkstra (cost)Fast, scalable — most common interior
EIGRPHybridBandwidth + delayCisco proprietary — fast convergence
BGPPath VectorPolicy-basedThe Internet's routing protocol — between ISPs

5.3 Spanning Tree Protocol (STP)

  • Prevents switching loops in redundant topologies
  • Elects a Root Bridge — lowest Bridge ID wins
  • Blocks redundant paths — only one active path at a time
  • RSTP (802.1w) = faster convergence version — know this one for the exam
# Useful show commands on Cisco switches:
show vlan brief              # See all VLANs
show interfaces trunk        # See trunk ports
show spanning-tree           # STP topology
show ip route                # Routing table
show arp                     # ARP cache (IP to MAC mappings)
Default Gateway: The router's IP address on your local subnet. Without it, your PC can reach local hosts but can't get to the internet. First thing to check when "internet is down."

6.3 Wireless Threats

  • Evil Twin: Rogue AP mimicking a legitimate one — users connect unknowingly
  • Deauth Attack: Forged packets kick users off, forcing reconnect (used to capture handshakes)
  • War Driving: Driving around scanning for open Wi-Fi networks
  • WPS Attack: Brute force the 8-digit WPS PIN — disable WPS!

7.3 Security Concepts

# Key terms to know cold:
IDS   - Intrusion Detection System  (detects, alerts — passive)
IPS   - Intrusion Prevention System (detects AND blocks — inline)
DMZ   - Demilitarized Zone (public-facing servers between two firewalls)
VPN   - Encrypted tunnel over public network
ACL   - Access Control List (permit/deny rules on routers/firewalls)
AAA   - Authentication, Authorization, Accounting (RADIUS / TACACS+)
IDS vs IPS: Think of IDS as a security camera (watches and records) and IPS as a security guard (watches AND stops the threat). IPS must be inline in the traffic path. IDS can be passive (tap or span port).

8. Troubleshooting Methodology

🧠 The troubleshooting steps are the SAME across all CompTIA exams. Memorize them once, use them everywhere.

  1. Identify the problem — Gather information, duplicate if possible, check error messages
  2. Establish theory of probable cause — Start at Layer 1 and work up (OSI bottom-up)
  3. Test the theory — Confirm or deny, escalate if needed
  4. Establish plan of action — Know your fix before touching anything
  5. Implement the solution — Make your change
  6. Verify full system functionality — Test everything, not just the reported issue
  7. Document findings — Write it down. Future you will thank you.

Network Troubleshooting Commands

# Connectivity
ping 8.8.8.8               # Test basic IP connectivity
ping -t 8.8.8.8            # Continuous ping (Windows)
tracert 8.8.8.8            # Trace path to destination (Windows)
traceroute 8.8.8.8         # Same thing (Linux/Mac)

# DNS
nslookup google.com        # Query DNS for a hostname
dig google.com             # Detailed DNS query (Linux)

# Interface & Config
ipconfig /all              # Full IP config (Windows)
ipconfig /release          # Release DHCP lease
ipconfig /renew            # Get new DHCP lease
ipconfig /flushdns         # Clear DNS cache
ip addr show               # IP config (Linux)

# Connections & Ports
netstat -an                # All active connections and ports
ss -tulpn                  # Listening ports (Linux)
arp -a                     # View ARP cache

# Advanced
pathping 8.8.8.8           # Combo ping + tracert (Windows)
nmap -sV 192.168.1.1       # Port scan target (use ethically!)

The #1 Network+ troubleshooting tip: Always check the physical layer first. Half of all "network is down" tickets are a unplugged cable or a dead switch port. Don't overthink it — check Layer 1 before you touch anything else.
