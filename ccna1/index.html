1.4 Reliable Network Characteristics

  • Fault Tolerance: Ability to continue operating when components fail — redundant paths
  • Scalability: Ability to grow and add users/devices without degrading performance
  • Quality of Service (QoS): Prioritizes certain traffic — voice/video over file downloads
  • Security: Confidentiality, Integrity, Availability (CIA triad)
Bandwidth vs Throughput vs Goodput: Bandwidth = theoretical maximum (like a highway speed limit). Throughput = actual measured data rate (real speed you get). Goodput = useful data only — excludes overhead, retransmissions. Goodput ≤ Throughput ≤ Bandwidth. Always.

3.3 Encapsulation & PDUs

Data travels down the stack — each layer adds a header (and sometimes trailer). This is called encapsulation. At the destination, each layer strips its header — called de-encapsulation.

Application Data
    → Transport adds TCP/UDP header    = SEGMENT
    → Network adds IP header           = PACKET
    → Data Link adds Frame header+FCS  = FRAME
    → Physical converts to bits        = BITS on wire

5. Data Link Layer Module 5 & 6

5.1 Data Link Layer Functions

  • Accepts packets from Network layer and packages them into frames
  • Controls how data is placed on and received from media
  • Provides error detection (not correction) via FCS (Frame Check Sequence)
  • Two sublayers: LLC (Logical Link Control — interfaces with Network layer) and MAC (Media Access Control — hardware addressing)

5.2 MAC Addresses

  • 48-bit (6-byte) address burned into NIC by manufacturer
  • Written as hex: AA:BB:CC:DD:EE:FF or AA-BB-CC-DD-EE-FF
  • First 3 bytes = OUI (Organizationally Unique Identifier) — identifies manufacturer
  • Last 3 bytes = device-specific identifier assigned by manufacturer
  • Unicast: One specific device
  • Broadcast: FF:FF:FF:FF:FF:FF — sent to ALL devices on segment
  • Multicast: Sent to a group of devices (begins with 01:00:5E for IPv4 multicast)

5.3 Ethernet Frame Structure

FieldSizePurpose
Preamble7 bytesSynchronization — alerts devices frame is coming
SFD (Start Frame Delimiter)1 byteMarks end of preamble, start of frame
Destination MAC6 bytesWhere the frame is going
Source MAC6 bytesWhere the frame came from
Type / Length2 bytesIdentifies upper-layer protocol (0x0800 = IPv4, 0x86DD = IPv6)
Data (Payload)46–1500 bytesEncapsulated packet from Network layer
FCS4 bytesCRC error detection — receiver recalculates and compares

5.4 Media Access Control Methods

MethodUsed ByHow It Works
CSMA/CDHalf-duplex Ethernet (legacy)Listen before transmit, detect collisions, back off and retry
CSMA/CA802.11 Wi-FiListen before transmit, try to AVOID collisions, use random backoff
Full DuplexModern switched EthernetSend and receive simultaneously — no collisions possible on switch ports
Why Wi-Fi uses CA not CD: Wireless devices can't detect collisions while transmitting (they can't hear over their own signal). So Wi-Fi tries to AVOID collisions instead of detecting them. This is why Wi-Fi is inherently less efficient than wired Ethernet.

6. Network Layer Module 7 & 8

6.1 Network Layer Functions

  • Addressing: Adds source and destination IP addresses to packets
  • Routing: Determines best path across networks to destination
  • De-encapsulation: Receives frames from Data Link, strips header, passes packet up
  • Encapsulation: Takes segments from Transport, adds IP header, passes frame down

6.2 IPv4 Packet Header Fields

FieldSizePurpose
Version4 bitsIPv4 = 4, IPv6 = 6
IHL (Header Length)4 bitsLength of header in 32-bit words
DSCP/ECN8 bitsQoS marking — traffic priority
Total Length16 bitsEntire packet size including header
TTL (Time to Live)8 bitsDecremented by 1 at each router — prevents routing loops. Reaches 0 = packet dropped.
Protocol8 bitsUpper layer: 6=TCP, 17=UDP, 1=ICMP
Source IP32 bitsSender's IP address
Destination IP32 bitsReceiver's IP address

6.3 How a Router Makes Forwarding Decisions

  1. Receives a frame, checks destination MAC — if it matches, de-encapsulates to get packet
  2. Checks destination IP in routing table for longest prefix match
  3. Encapsulates packet in new frame with next-hop's MAC address as destination
  4. Forwards out the appropriate interface
  5. Decrements TTL by 1
! View routing table on Cisco router:
Router# show ip route

! Output legend:
! C = Directly connected network
! L = Local (router's own interface IP)
! S = Static route (manually configured)
! O = OSPF learned route
! R = RIP learned route
! * = default route candidate

! Example routing table entry:
! C    192.168.1.0/24 is directly connected, GigabitEthernet0/0
! S    0.0.0.0/0 [1/0] via 10.0.0.1     (default route)

6.4 Routing Decision — Longest Prefix Match

When multiple routes match a destination, the router picks the most specific (longest prefix/highest subnet mask). A /28 beats a /24 which beats a /0 (default route).

The default route (0.0.0.0/0): This is the "gateway of last resort" — if no other route matches, send it here. On a home router, this points to your ISP. On a corporate router, it points upstream toward the internet. Without a default route, unmatched packets are simply dropped.

7.4 TCP Windowing & Flow Control

  • Window size: How many bytes sender can transmit before waiting for ACK
  • Sliding window: Window advances as ACKs are received — allows continuous flow
  • Slow start: TCP begins with small window, grows exponentially until congestion detected
  • Congestion avoidance: When packet loss detected, window size reduced
Socket = IP + Port: A socket uniquely identifies a communication endpoint. 192.168.1.10:80 is a socket. A TCP connection is identified by the 4-tuple: Source IP, Source Port, Destination IP, Destination Port. This is how one server can have thousands of simultaneous HTTP connections on port 80.

8.2 DNS Resolution Process

  1. User types www.cisco.com in browser
  2. PC checks its local DNS cache — if found, done
  3. If not cached, PC sends query to its configured DNS server (Recursive Resolver)
  4. Resolver checks its cache — if found, returns answer
  5. If not cached, Resolver queries Root DNS server → gets referral to .com TLD server
  6. Resolver queries .com TLD server → gets referral to cisco.com Authoritative server
  7. Resolver queries cisco.com Authoritative server → gets IP address
  8. Resolver caches result, returns IP to PC
  9. PC caches result, browser connects to IP address

9. Address Resolution Protocol (ARP) Module 9

9.1 Why ARP Exists

IP packets need to be wrapped in frames. Frames need MAC addresses. But you only know the destination IP. ARP maps IP addresses → MAC addresses on a local network segment.

9.2 ARP Process

PC-A (192.168.1.10) wants to send to PC-B (192.168.1.20)

1. PC-A checks ARP cache: "Do I know the MAC for 192.168.1.20?"
   Command: arp -a    (view ARP cache)

2. If NOT in cache:
   PC-A sends ARP Request (BROADCAST):
   "Who has 192.168.1.20? Tell 192.168.1.10"
   Destination MAC: FF:FF:FF:FF:FF:FF (all devices receive this)

3. PC-B receives broadcast, recognizes its own IP:
   PC-B sends ARP Reply (UNICAST) back to PC-A:
   "192.168.1.20 is at AA:BB:CC:DD:EE:FF"

4. PC-A stores MAC in ARP cache (temporary — expires in ~4 hours)

5. PC-A can now build the frame with PC-B's MAC address

9.3 ARP for Remote Destinations

If destination is on a different network, the host ARPs for the default gateway's MAC — not the destination. The router then handles forwarding toward the destination.

ARP Spoofing (Security concern): ARP has no authentication — any device can send a fake ARP reply claiming to be any IP. Attackers use this for Man-in-the-Middle attacks. This is why Dynamic ARP Inspection (DAI) exists on managed switches. Know this for both CCNA and Security+.

11. IPv4 Addressing & Subnetting Module 11 & 12

11.1 IPv4 Address Structure

  • 32-bit address — written as 4 octets in dotted decimal: 192.168.1.100
  • Two parts: Network portion (identified by subnet mask) and Host portion
  • Subnet mask identifies which bits are network bits: 255.255.255.0 = first 3 octets are network
  • CIDR notation: /24 means 24 network bits (same as 255.255.255.0)

11.3 Subnetting Steps — Worked Example

Problem: Subnet 192.168.1.0/24 into 4 equal subnets

Step 1: How many bits to borrow?
        2^n >= number of subnets needed
        2^2 = 4 ✅  →  borrow 2 bits  →  new prefix = /26

Step 2: New subnet mask?
        /26 = 255.255.255.192

Step 3: Block size (increment)?
        256 - 192 = 64  →  subnets increment by 64

Step 4: List the subnets:
        Subnet 1: 192.168.1.0/26
                  Network:   192.168.1.0
                  First host: 192.168.1.1
                  Last host:  192.168.1.62
                  Broadcast:  192.168.1.63

        Subnet 2: 192.168.1.64/26
                  Network:   192.168.1.64
                  First host: 192.168.1.65
                  Last host:  192.168.1.126
                  Broadcast:  192.168.1.127

        Subnet 3: 192.168.1.128/26
                  Network:   192.168.1.128
                  First host: 192.168.1.129
                  Last host:  192.168.1.190
                  Broadcast:  192.168.1.191

        Subnet 4: 192.168.1.192/26
                  Network:   192.168.1.192
                  First host: 192.168.1.193
                  Last host:  192.168.1.254
                  Broadcast:  192.168.1.255
Subnetting shortcut — the "block size" trick: Subtract the last non-zero octet of the subnet mask from 256. That's your block size (increment between subnets). For 255.255.255.192: 256 - 192 = 64. Your subnets start at 0, 64, 128, 192. Network address = first, Broadcast = next subnet minus 1, Hosts = everything in between.

12. IPv6 Addressing Module 13 & 14

12.1 Why IPv6?

  • IPv4 = 32-bit = ~4.3 billion addresses — exhausted
  • IPv6 = 128-bit = 340 undecillion addresses (3.4 × 10³⁸) — effectively unlimited
  • No need for NAT — every device gets a globally unique address
  • Built-in IPsec support, improved header (simpler, more efficient)
  • No broadcast — uses multicast and anycast instead

12.2 IPv6 Address Format & Compression Rules

Full address:  2001:0DB8:0000:0001:0000:0000:0000:0001

Rule 1 — Omit leading zeros in each group:
           2001:DB8:0:1:0:0:0:1

Rule 2 — Replace ONE sequence of consecutive all-zero groups with ::
           2001:DB8:0:1::1

! You can only use :: ONCE per address
! :: represents one or more groups of 0000

More examples:
  Full:      FE80:0000:0000:0000:0202:B3FF:FE1E:8329
  Compressed: FE80::202:B3FF:FE1E:8329

  Loopback full:      0000:0000:0000:0000:0000:0000:0000:0001
  Loopback compressed: ::1

12.3 IPv6 Address Types

TypePrefixDescription
Global Unicast (GUA)2000::/3Publicly routable — like public IPv4. Starts with 2 or 3.
Link-Local (LLA)FE80::/10Auto-configured on every IPv6 interface. Not routable. Required for IPv6 to work.
Unique LocalFC00::/7Private — like RFC 1918. Not routable on internet.
Loopback::1/128Like 127.0.0.1 in IPv4 — test local stack
Unspecified::/128Like 0.0.0.0 in IPv4 — source address when no address assigned yet

12.4 IPv6 Configuration on Cisco Devices

! Enable IPv6 routing (required on routers)
R1(config)# ipv6 unicast-routing

! Configure GUA on interface
R1(config)# interface gigabitethernet 0/0
R1(config-if)# ipv6 address 2001:DB8:ACAD:1::1/64
R1(config-if)# no shutdown

! Configure Link-Local manually (optional — auto-generated by default)
R1(config-if)# ipv6 address FE80::1 link-local

! EUI-64 — auto-generate interface ID from MAC address
R1(config-if)# ipv6 address 2001:DB8:ACAD:1::/64 eui-64

! View IPv6 info
R1# show ipv6 interface brief
R1# show ipv6 route
Link-Local is MANDATORY: Every IPv6-enabled interface automatically generates a link-local address (FE80::/10) using EUI-64 from its MAC address. This happens even if you never configure a GUA. IPv6 neighbor discovery, routing protocols, and default gateway communication all use link-local addresses. If you see FE80:: — that's normal and expected.

13.2 How Traceroute Works

traceroute / tracert works by incrementing TTL:

Packet 1: TTL=1 → First router decrements to 0, drops packet, sends ICMP "Time Exceeded" back
           → We learn Hop 1's IP and round-trip time

Packet 2: TTL=2 → First router passes (TTL=1), second router drops, sends ICMP back
           → We learn Hop 2's IP and round-trip time

...continues until destination reached (sends ICMP Echo Reply instead of Time Exceeded)

Windows:  tracert 8.8.8.8
Linux/Mac: traceroute 8.8.8.8
Cisco IOS: traceroute 8.8.8.8

13.3 Network Testing Methodology

! Systematic bottom-up testing approach:

! Layer 1 — Physical
! Check: cable connected? link light on NIC and switch port?

14.3 Most-Used Show Commands

show ssh                         ! SSH session info
show users                       ! Who is logged in
show history                     ! Command history
show clock                       ! Current time

The most important IOS habit: After making ANY change, always verify with a show command. show ip interface brief and show running-config are your two best friends. And always save with copy running-config startup-config before you leave a device — if it reboots and you didn't save, everything you did is gone.
