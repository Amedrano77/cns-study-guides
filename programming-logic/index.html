1. Structured Programming Concepts Module 1

1.1 What is Structured Programming?

Structured programming is a programming paradigm that improves code clarity, quality, and development time by using three fundamental control structures — sequence, selection, and iteration. Every program, no matter how complex, can be built from these three building blocks. No spaghetti code, no uncontrolled jumps — just clean, logical flow.

1.2 The Three Control Structures

StructureDescriptionExamples
SequenceExecute statements one after another in order — top to bottomVariable assignment, print statements, calculations
SelectionChoose between paths based on a conditionif/elif/else (Python), if/elseif/else (PowerShell), switch/case
Iteration (Loops)Repeat a block of code while a condition is true or for each item in a collectionfor, while, foreach, do-while

1.3 Algorithm Design Tools

ToolDescriptionUse Case
PseudocodePlain English description of an algorithm — no specific syntaxPlanning logic before coding — language agnostic
FlowchartVisual diagram using standard shapes to represent program flowVisualizing decision points, loops, and process flow
IPO ChartInput → Process → Output tableSimple program planning — what goes in, what happens, what comes out

1.4 Flowchart Symbols

ShapeNameRepresents
OvalTerminalStart or End of program
RectangleProcessA computation or action step
DiamondDecisionA yes/no or true/false condition
ParallelogramInput/OutputReading input or displaying output
ArrowFlow LineDirection of program flow
Always plan before you code. Professional developers spend more time designing than typing. A 10-minute pseudocode session saves hours of debugging. Draw it out, think through every condition, every edge case — then write the code. The students who skip this step are the ones still debugging at midnight.

2. Scripting vs. Programming Module 1

2.1 Key Differences

FeatureScriptingProgramming
ExecutionInterpreted at runtime — no compilation stepOften compiled to machine code or bytecode first
SpeedSlower — interpreted line by lineFaster — pre-compiled execution
PurposeAutomate tasks, glue programs together, system administrationBuild applications, operating systems, databases
ComplexityUsually shorter, task-focusedCan be very large and complex
ExamplesPowerShell, Bash, Python scripts, JavaScriptC, C++, Java, C# (compiled)
EnvironmentNeeds an interpreter (PowerShell engine, Python interpreter)Needs a compiler (gcc, javac)

2.2 Where Python Sits

  • Python is both a scripting language (great for automation and quick tasks) AND a full programming language (used to build web apps, AI, data science, games)
  • Python is interpreted — the Python interpreter executes code line by line
  • Python compiles to bytecode (.pyc) internally — faster on subsequent runs but still interpreted
  • This makes Python incredibly flexible — run a 3-line script or build a million-line application

2.3 Why Learn Both PowerShell AND Python?

  • PowerShell — native to Windows, deep OS integration, essential for sysadmin tasks, Active Directory, Azure
  • Python — cross-platform, massive library ecosystem, data science, web, network automation (Netmiko, NAPALM)
  • Together they cover virtually every automation need in IT — Windows infrastructure with PowerShell, cross-platform and network automation with Python

3. PowerShell Fundamentals Module 2 PowerShell

3.1 What is PowerShell?

PowerShell is a task automation framework from Microsoft consisting of a command-line shell and a scripting language built on .NET. Unlike traditional command prompts that work with text, PowerShell works with objects — structured data with properties and methods. This makes it incredibly powerful for system administration.

4. PowerShell Execution Policy & Providers Module 2 PowerShell

4.1 Execution Policy

Execution Policy controls which PowerShell scripts are allowed to run. It's a security feature — not an unbreakable barrier, but it prevents accidental execution of untrusted scripts.

PolicyBehavior
RestrictedDefault on Windows — no scripts allowed, only interactive commands
AllSignedOnly scripts signed by a trusted publisher can run
RemoteSignedLocal scripts run freely; downloaded scripts must be signed
UnrestrictedAll scripts run — warns before running downloaded scripts
BypassNothing blocked, no warnings — used in automation pipelines
UndefinedNo policy set at this scope — inherits from higher scope
# Check current policy
Get-ExecutionPolicy
Get-ExecutionPolicy -List           # Show policy at all scopes

# Set policy (requires admin)
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
Set-ExecutionPolicy RemoteSigned -Scope LocalMachine

# Run a single script bypassing policy (doesn't change system policy)
PowerShell.exe -ExecutionPolicy Bypass -File .\myscript.ps1

5. PowerShell Pipeline & Formatting Module 4 PowerShell

5.1 The Pipeline

The PowerShell pipeline (|) passes objects from one command to the next — not just text. This is what makes PowerShell so powerful. You can chain commands together to filter, sort, format, and export data in one line.

# Basic pipeline — get processes, sort by CPU usage, show top 10
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10

# Filter with Where-Object
Get-Process | Where-Object { $_.CPU -gt 100 }       # $_ = current object in pipeline
Get-Service | Where-Object { $_.Status -eq "Running" }

# Select specific properties
Get-Process | Select-Object Name, CPU, WorkingSet

# Pipe to format commands
Get-Process | Format-Table Name, CPU, Id -AutoSize   # Table format
Get-Process | Format-List Name, CPU, Id              # List format
Get-Service | Format-Wide Name -Column 4             # Wide format

# Pipe to export
Get-Process | Export-Csv "C:\processes.csv" -NoTypeInformation
Get-Service | Export-Csv "C:\services.csv" -NoTypeInformation
Get-Process | ConvertTo-Json                         # JSON output
Get-Process | Out-File "C:\processes.txt"            # Plain text file
Get-Process | Out-GridView                           # Pop-up sortable table

5.2 Common Pipeline Cmdlets

CmdletPurposeExample
Where-ObjectFilter objects by conditionWhere-Object { $_.Status -eq "Running" }
Select-ObjectChoose properties or limit resultsSelect-Object Name, CPU -First 5
Sort-ObjectSort by propertySort-Object CPU -Descending
Group-ObjectGroup by propertyGroup-Object Status
Measure-ObjectCount, sum, averageMeasure-Object CPU -Sum -Average
ForEach-ObjectRun action for each objectForEach-Object { $_.Name.ToUpper() }
Tee-ObjectSend pipeline to file AND to next cmdletTee-Object -FilePath "log.txt"

10.2 Creating Classes in Python

# ===== BASIC CLASS =====
class Student:
    # Class variable — shared by ALL instances
    school = "TSTC"

    # __init__ is the constructor — runs when object is created
    def __init__(self, name, age, major):
        # Instance variables — unique to each object
        self.name = name
        self.age = age
        self.major = major
        self.grades = []           # Empty list for this student's grades

    # Instance method
    def add_grade(self, grade):
        self.grades.append(grade)

    def get_gpa(self):
        if not self.grades:
            return 0.0
        return sum(self.grades) / len(self.grades)

    def introduce(self):
        print(f"Hi, I'm {self.name}, {self.age} years old, studying {self.major} at {self.school}.")

    # __str__ — defines what print(object) shows
    def __str__(self):
        return f"Student({self.name}, {self.major}, GPA: {self.get_gpa():.2f})"


# ===== CREATE OBJECTS (instances) =====
student1 = Student("John Smith", 20, "CNS")
student2 = Student("Alice Jones", 22, "IT")

# Call methods
student1.introduce()
student1.add_grade(95)
student1.add_grade(87)
student1.add_grade(92)
print(f"{student1.name}'s GPA: {student1.get_gpa():.2f}")

# Access attributes
print(student1.name)           # John Smith
print(Student.school)          # TSTC (class variable)
print(student1)                # Uses __str__: Student(John Smith, CNS, GPA: 91.33)

10.3 Inheritance

# ===== BASE CLASS =====
class Animal:
    def __init__(self, name, species):
        self.name = name
        self.species = species

    def speak(self):
        return "..."               # Generic — will be overridden

    def describe(self):
        return f"{self.name} is a {self.species}"

# ===== CHILD CLASS =====
class Dog(Animal):                 # Dog inherits from Animal
    def __init__(self, name, breed):
        super().__init__(name, "Canis familiaris")  # Call parent __init__
        self.breed = breed

    def speak(self):               # Override parent method
        return f"{self.name} says: Woof!"

    def fetch(self, item):
        return f"{self.name} fetches the {item}!"

class Cat(Animal):
    def __init__(self, name):
        super().__init__(name, "Felis catus")

    def speak(self):               # Different implementation, same method name
        return f"{self.name} says: Meow!"

# ===== POLYMORPHISM =====
animals = [Dog("Rex", "German Shepherd"), Cat("Whiskers"), Dog("Buddy", "Labrador")]

for animal in animals:
    print(animal.speak())          # Each calls ITS version of speak()
    print(animal.describe())       # Inherited from Animal

# isinstance() — check if object is instance of a class
isinstance(animals[0], Dog)        # True
isinstance(animals[0], Animal)     # True — Dog IS-A Animal
isinstance(animals[0], Cat)        # False

10.4 Encapsulation — Private Attributes

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance   # __ prefix = private attribute

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"Deposited ${amount}. Balance: ${self.__balance}")

    def withdraw(self, amount):
        if amount > self.__balance:
            print("Insufficient funds")
        elif amount > 0:
            self.__balance -= amount
            print(f"Withdrew ${amount}. Balance: ${self.__balance}")

    def get_balance(self):         # Getter method — controlled access
        return self.__balance

account = BankAccount("Adrian", 1000)
account.deposit(500)
account.withdraw(200)
print(account.get_balance())       # 1300
# print(account.__balance)         # AttributeError — private!

# ===== SCRIPT TEMPLATE — script.ps1 =====
# Always start scripts with a comment block describing purpose
<#
.SYNOPSIS
    System health check script
.DESCRIPTION
    Checks CPU, memory, disk, and running services
.AUTHOR
    Adrian M. — TSTC CNS
.DATE
    2025
#>

param(
    [string]$ComputerName = $env:COMPUTERNAME,
    [string]$OutputPath = "C:\Reports"
)

# Function definitions
function Get-DiskHealth {
    Get-PSDrive -PSProvider FileSystem | Select-Object Name,
        @{N="Used(GB)"; E={[math]::Round($_.Used/1GB, 2)}},
        @{N="Free(GB)"; E={[math]::Round($_.Free/1GB, 2)}},
        @{N="Total(GB)"; E={[math]::Round(($_.Used+$_.Free)/1GB, 2)}}
}

function Get-MemoryUsage {
    $os = Get-CimInstance Win32_OperatingSystem
    $total = [math]::Round($os.TotalVisibleMemorySize/1MB, 2)
    $free  = [math]::Round($os.FreePhysicalMemory/1MB, 2)
    $used  = $total - $free
    [PSCustomObject]@{
        TotalGB = $total
        UsedGB  = $used
        FreeGB  = $free
        PctUsed = [math]::Round(($used/$total)*100, 1)
    }
}

# Main execution
Write-Host "=== System Health Report: $ComputerName ===" -ForegroundColor Cyan
Write-Host "`nDisk Usage:"
Get-DiskHealth | Format-Table -AutoSize

Write-Host "`nMemory Usage:"
Get-MemoryUsage | Format-List

Write-Host "`nTop 5 CPU Processes:"
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5 Name, CPU, Id | Format-Table

# ===== GOOD COMMENTS =====

# ===== DOCSTRINGS =====
def calculate_gpa(grades):
    """
    Calculate the Grade Point Average from a list of grades.

    Args:
        grades (list): A list of numeric grade values (0-100)

    Returns:
        float: The average grade, or 0.0 if the list is empty

    Raises:
        TypeError: If grades is not a list

    Example:
        >>> calculate_gpa([95, 87, 92, 78])
        88.0
    """
    if not isinstance(grades, list):
        raise TypeError("grades must be a list")
    if not grades:
        return 0.0
    return sum(grades) / len(grades)

14.4 Testing Your Code

# ===== PYTHON UNIT TESTING =====
import unittest
from my_module import calculate_gpa    # Import function to test

class TestGPACalculator(unittest.TestCase):

    def test_normal_grades(self):
        result = calculate_gpa([90, 85, 92])
        self.assertAlmostEqual(result, 89.0, places=1)

    def test_empty_list(self):
        result = calculate_gpa([])
        self.assertEqual(result, 0.0)

    def test_single_grade(self):
        result = calculate_gpa([100])
        self.assertEqual(result, 100.0)

    def test_invalid_input(self):
        with self.assertRaises(TypeError):
            calculate_gpa("not a list")

if __name__ == "__main__":
    unittest.main()

# Run tests:  python -m pytest test_gpa.py -v
The best programmers write tests FIRST (Test-Driven Development / TDD). Write the test that describes what you WANT the code to do, watch it fail, then write the code to make it pass. It sounds backwards but it forces you to think clearly about requirements before you write a single line of production code.
