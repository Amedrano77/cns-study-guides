1.3 Password Attacks

AttackHow It WorksDefense
Brute ForceTry every possible combinationAccount lockout, long passwords
DictionaryTry list of common words/passwordsComplex passwords, passphrases
Rainbow TablePre-computed hash lookup tablePassword salting
Credential StuffingUse leaked username/password combosUnique passwords per site, MFA
Password SprayingTry one common password against many accountsMFA, lockout policies
Salting passwords: A random value added to a password before hashing. Even if two users have the same password, their hashes will be different. This defeats rainbow table attacks. Always salt — never store plain text passwords.

2.3 PKI & Certificates

  • CA (Certificate Authority): Trusted entity that issues digital certificates
  • Root CA: Top of the trust chain — offline for security
  • Intermediate CA: Issues end-entity certs on behalf of Root CA
  • Certificate: Binds a public key to an identity (name, domain)
  • CRL (Certificate Revocation List): List of revoked certs
  • OCSP: Online check if a cert is revoked — faster than CRL
  • CSR (Certificate Signing Request): Request you send to CA to get a cert
How HTTPS works (simplified): Server sends its certificate → browser verifies it's signed by a trusted CA → they use asymmetric crypto to exchange a symmetric session key → all traffic encrypted with that session key. Asymmetric for the handshake, symmetric for speed.

3.3 AAA Protocols

AAA = Authentication, Authorization, Accounting

RADIUS  - UDP ports 1812/1813
        - Encrypts only the password
        - Common for network access (Wi-Fi, VPN)

TACACS+ - TCP port 49
        - Encrypts the ENTIRE payload
        - Cisco proprietary
        - Better for device administration (routers, switches)

LDAP    - TCP port 389 (636 for LDAPS)
        - Directory services — Active Directory uses this
        - Stores user/group info

Kerberos - UDP/TCP port 88
         - Ticket-based authentication
         - Default in Windows Active Directory domains
         - Uses KDC (Key Distribution Center)

🔑 MFA tip: Two factors must be from DIFFERENT categories. Password + PIN = NOT MFA (both are "something you know"). Password + phone OTP = real MFA.

4.3 Cloud Security Concepts

TermMeaning
Shared ResponsibilityCloud provider secures the infrastructure; YOU secure your data and configs
CASBCloud Access Security Broker — enforces security policies between users and cloud services
CSPMCloud Security Posture Management — finds misconfigurations in cloud environments
FaaS / ServerlessFunctions as a Service — you write code, provider manages everything else

Shared Responsibility in plain English: AWS/Azure/GCP won't let someone physically steal their servers. But if YOU misconfigure an S3 bucket to be public and expose customer data — that's on YOU, not them. The cloud provider secures the building; you secure what's inside it.

Security Controls by Type: Preventive (stops attack — firewall, locks), Detective (finds attack — IDS, logs, cameras), Corrective (fixes after attack — backups, patches), Deterrent (discourages attack — warning signs, policies). Know all four for the exam.

7. Incident Response & Forensics

7.1 Incident Response Steps

  1. Preparation — Policies, tools, trained team ready before incident occurs
  2. Identification — Detect and confirm an incident has occurred
  3. Containment — Stop the spread — isolate affected systems (short-term then long-term)
  4. Eradication — Remove the threat — malware, backdoors, compromised accounts
  5. Recovery — Restore systems to normal operation, monitor closely
  6. Lessons Learned — Document what happened, update policies, prevent recurrence

7.2 Digital Forensics Concepts

ConceptDescription
Chain of CustodyDocumented trail of who handled evidence and when — required for court
Order of VolatilityCollect most volatile evidence first: RAM → swap → disk → logs → archives
Legal HoldPreserve all evidence related to litigation — stop normal deletion
Write BlockerHardware device preventing any writes to evidence drive
Forensic ImageBit-for-bit copy of storage — never work on original evidence

🧊 First rule of forensics: Never work on original evidence. Always image it first. If you alter the original, it may be inadmissible in court.

7.3 Log Sources for Investigations

# Where to look when investigating an incident:
SIEM         - Aggregates logs from all sources — your investigation hub
Firewall     - What traffic was allowed/blocked, when, from where
DNS logs     - What domains were resolved — catches C2 callbacks
Auth logs    - Login successes/failures — who accessed what, when
Endpoint     - Process execution, file changes, network connections
Email logs   - Phishing delivery, malicious attachments
NetFlow      - Traffic volume/patterns — spot data exfiltration

8. Troubleshooting & Tools

Security Troubleshooting Commands

# Check open ports and connections
netstat -an              # All connections and listening ports
ss -tulpn                # Linux — listening ports with process names

# Check running processes (spot malware)
ps aux                   # Linux process list
tasklist                 # Windows process list

# File integrity
md5sum file.txt          # Generate MD5 hash
sha256sum file.txt       # Generate SHA-256 hash (preferred)
# Compare hashes before/after to verify integrity

# Check scheduled tasks (persistence mechanism)
crontab -l               # Linux cron jobs
schtasks /query          # Windows scheduled tasks

# Network traffic analysis
tcpdump -i eth0          # Capture packets (Linux)
wireshark                # GUI packet analyzer

# Log review
journalctl -xe           # Recent system errors (Linux)
tail -f /var/log/auth.log  # Live auth log monitoring

Quick Security Checklist

CheckWhy
Patches up to date?Most exploits target known, unpatched vulnerabilities
MFA enabled?Stops 99%+ of credential-based attacks
Principle of Least Privilege?Users should only have access they need — nothing more
Backups tested?Untested backups are not backups — verify restores work
Default credentials changed?Admin/admin is the first thing attackers try
Logging & monitoring on?You can't respond to what you can't see
The Security+ exam mindset: CompTIA wants you to think like a security professional, not just memorize definitions. When you see a scenario question, ask yourself: "What is the BEST control that addresses the ROOT cause?" Preventive controls are usually preferred over detective ones — it's better to stop an attack than detect it after the damage is done.
