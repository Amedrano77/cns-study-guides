1. Single-Area OSPFv2 Concepts Module 1

1.1 Why OSPF?

Static routes don't scale. RIP is limited to 15 hops and converges slowly. OSPF is a Link-State routing protocol — each router builds a complete map of the network, runs Dijkstra's shortest path algorithm, and makes intelligent routing decisions. OSPF converges fast, scales to large networks, and is the most common interior gateway protocol in enterprise networks.

1.2 OSPF Key Concepts

TermDefinition
Link-StateEach router knows the entire topology — builds a map, not just a next-hop list
LSA (Link State Advertisement)Packet containing a router's link info — flooded to all OSPF routers
LSDB (Link State Database)The complete topology map built from all LSAs — must be identical on all routers in an area
SPF AlgorithmDijkstra's algorithm — calculates shortest path tree from LSDB
AreaGroup of routers sharing the same LSDB — Area 0 = backbone area
DR/BDRDesignated Router / Backup DR — elected on multi-access networks to reduce LSA flooding
Hello PacketsSent every 10 seconds on Ethernet — discovers neighbors, maintains adjacency
Dead Interval4x Hello (40 sec default on Ethernet) — if no Hello received, neighbor declared dead
Router ID (RID)32-bit number that uniquely identifies each OSPF router — looks like an IP address

1.3 Router ID Selection Order

  1. Manually configured with router-id command (highest priority)
  2. Highest IP address on any active loopback interface
  3. Highest IP address on any active physical interface
Always manually set the Router ID. Relying on highest IP is unpredictable — if an interface goes up or down, the RID can change and cause OSPF to reset. Use a loopback interface with a /32 mask for the RID. Loopbacks never go down unless you shut them manually, making OSPF stable.

1.4 OSPF Neighbor States

StateMeaning
DownNo Hellos received — no neighbor relationship
InitHello received but our Router ID not in it yet
2-WayBidirectional communication — DR/BDR election happens here
ExStartMaster/Slave negotiation for database exchange
ExchangeDBD (Database Description) packets exchanged — summary of LSDB
LoadingLSR/LSU packets — requesting and receiving missing LSAs
Full✅ Fully adjacent — LSDBs synchronized, routing can begin

1.5 DR/BDR Election on Multi-Access Networks

  • On Ethernet segments, OSPF elects a DR (Designated Router) and BDR (Backup DR)
  • All other routers (DROther) form adjacency ONLY with DR and BDR — not with each other
  • Reduces LSA flooding: instead of n(n-1)/2 adjacencies, only n adjacencies needed
  • Election: Highest OSPF priority wins (default = 1). Tie → highest Router ID wins
  • Priority 0 = never becomes DR or BDR
  • Election is non-preemptive — changing priority doesn't kick out existing DR

1.6 OSPF Cost Calculation

OSPF metric = Cost. Cost = Reference Bandwidth / Interface Bandwidth. Default reference bandwidth = 100 Mbps.

InterfaceBandwidthDefault CostCost with 1Gbps Reference
Serial (T1)1.544 Mbps64647
FastEthernet100 Mbps110
GigabitEthernet1000 Mbps11
10-GigabitEthernet10,000 Mbps11
FastEthernet and GigabitEthernet both have cost 1 by default — that's wrong! Change the reference bandwidth to 10000 (10 Gbps) on ALL routers so faster links get lower costs. Must be consistent on every router or you'll get routing loops. Do this before any other OSPF config.

2. Single-Area OSPFv2 Configuration Module 2 Lab Heavy

2.1 Basic OSPFv2 Configuration

! ===== STEP 1: Enable OSPF and set Router ID =====
R1(config)# router ospf 1                    ! Process ID (1-65535) — local significance only
R1(config-router)# router-id 1.1.1.1         ! Manually set Router ID (best practice)

! ===== STEP 2: Fix reference bandwidth (do on ALL routers) =====
R1(config-router)# auto-cost reference-bandwidth 10000   ! 10 Gbps reference

! ===== STEP 3: Advertise networks =====
! Wildcard mask = inverse of subnet mask (255.255.255.255 - subnet mask)
! /24 = mask 255.255.255.0 → wildcard 0.0.0.255
! /30 = mask 255.255.255.252 → wildcard 0.0.0.3

R1(config-router)# network 192.168.10.0 0.0.0.255 area 0   ! Advertise LAN
R1(config-router)# network 10.0.0.0 0.0.0.3 area 0         ! Advertise WAN link

! ===== ALTERNATIVE: network command with host wildcard =====
R1(config-router)# network 192.168.10.1 0.0.0.0 area 0    ! Exact interface IP

! ===== ALTERNATIVE: Enable OSPF directly on interface (modern way) =====
R1(config)# interface gi0/0
R1(config-if)# ip ospf 1 area 0              ! Enable OSPF process 1 on this interface

! ===== STEP 4: Set passive interfaces (don't send Hellos on LAN-facing ports) =====
R1(config-router)# passive-interface gi0/0   ! Specific interface
R1(config-router)# passive-interface default ! All interfaces passive by default
R1(config-router)# no passive-interface gi0/1 ! Then un-passive the OSPF-facing links

! ===== STEP 5: Default route redistribution =====
R1(config)# ip route 0.0.0.0 0.0.0.0 [ISP-next-hop]       ! Static default to ISP
R1(config-router)# default-information originate            ! Share default route via OSPF

2.2 OSPF Tuning

! ===== HELLO & DEAD INTERVALS =====
R1(config)# interface gi0/1
R1(config-if)# ip ospf hello-interval 5      ! Hello every 5 sec (default=10 on Ethernet)
R1(config-if)# ip ospf dead-interval 20      ! Dead after 20 sec (must match neighbor!)

! ===== OSPF PRIORITY (DR/BDR election) =====
R1(config)# interface gi0/0
R1(config-if)# ip ospf priority 200          ! Higher = more likely DR (0 = never DR)

! ===== INTERFACE COST (manual override) =====
R1(config)# interface gi0/1
R1(config-if)# ip ospf cost 10               ! Override calculated cost

! ===== LOOPBACK INTERFACE (stabilize RID) =====
R1(config)# interface loopback 0
R1(config-if)# ip address 1.1.1.1 255.255.255.255   ! /32 — host route
R1(config-if)# ip ospf 1 area 0             ! Optionally advertise loopback

! ===== OSPF AUTHENTICATION =====
R1(config)# interface gi0/1
R1(config-if)# ip ospf authentication message-digest
R1(config-if)# ip ospf message-digest-key 1 md5 OSPFpass123

2.3 OSPFv3 for IPv6

! OSPFv3 handles IPv6 routing — similar to OSPFv2 but for IPv6

R1(config)# ipv6 unicast-routing               ! Enable IPv6 routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 1.1.1.1

! Enable on interface (OSPFv3 uses interface commands, not network statements)
R1(config)# interface gi0/0
R1(config-if)# ipv6 ospf 1 area 0

! Passive interface
R1(config)# ipv6 router ospf 1
R1(config-rtr)# passive-interface gi0/0

4. ACL Concepts Module 4

4.1 What ACLs Do

  • ACLs are ordered lists of permit or deny statements
  • Applied to a router interface — filter traffic in or out
  • Processed top to bottom — first match wins, processing stops
  • Implicit deny all at the end of every ACL — if nothing matches, traffic is dropped
  • One ACL per interface, per direction, per protocol (one IPv4 in, one IPv4 out)

4.2 ACL Types

TypeNumber RangeFilters OnPlacement Rule
Standard IPv41–99, 1300–1999Source IP onlyPlace CLOSE to destination
Extended IPv4100–199, 2000–2699Source IP, Dest IP, Protocol, PortPlace CLOSE to source
NamedAny nameStandard or Extended rulesSame placement rules apply
ACL placement rule explained: Standard ACLs only filter by source IP — placed close to destination so they don't accidentally block traffic from reaching other parts of the network. Extended ACLs filter on source + destination — placed close to source to stop unwanted traffic as early as possible, saving bandwidth.

4.3 Wildcard Masks

Wildcard masks work opposite to subnet masks: 0 = must match, 1 = ignore (wildcard).

Subnet MaskWildcard MaskMatches
255.255.255.2550.0.0.0Exact host match
255.255.255.00.0.0.255Entire /24 subnet
255.255.0.00.0.255.255Entire /16 subnet
255.0.0.00.255.255.255Entire /8 subnet
any255.255.255.255Any address (0.0.0.0 255.255.255.255)
host0.0.0.0Exact single host (192.168.1.1 0.0.0.0)

5. ACLs for IPv4 Configuration Module 5 Lab Heavy

5.1 Standard ACL Configuration

! ===== NUMBERED STANDARD ACL =====
R1(config)# access-list 10 remark Block host 192.168.1.100
R1(config)# access-list 10 deny host 192.168.1.100        ! Deny specific host
R1(config)# access-list 10 permit 192.168.1.0 0.0.0.255   ! Permit rest of subnet
! Implicit deny any at end

! Apply to interface — close to destination
R1(config)# interface gi0/1
R1(config-if)# ip access-group 10 out                     ! Filter outbound traffic

! ===== NAMED STANDARD ACL (preferred — easier to edit) =====
R1(config)# ip access-list standard BLOCK_HOST
R1(config-std-nacl)# remark Deny specific host, permit subnet
R1(config-std-nacl)# 10 deny host 192.168.1.100           ! Sequence number 10
R1(config-std-nacl)# 20 permit 192.168.1.0 0.0.0.255      ! Sequence number 20
R1(config-std-nacl)# exit

R1(config)# interface gi0/1
R1(config-if)# ip access-group BLOCK_HOST out

5.2 Extended ACL Configuration

! ===== NAMED EXTENDED ACL =====
R1(config)# ip access-list extended INTERNET-FILTER

! Deny Telnet from any source to any destination
R1(config-ext-nacl)# 10 deny tcp any any eq 23

! Permit web traffic from LAN to internet
R1(config-ext-nacl)# 20 permit tcp 192.168.10.0 0.0.0.255 any eq 80
R1(config-ext-nacl)# 30 permit tcp 192.168.10.0 0.0.0.255 any eq 443

! Permit DNS
R1(config-ext-nacl)# 40 permit udp 192.168.10.0 0.0.0.255 any eq 53

! Permit ICMP (ping) — only from inside LAN
R1(config-ext-nacl)# 50 permit icmp 192.168.10.0 0.0.0.255 any

! Permit established TCP sessions returning from internet (stateless return traffic)
R1(config-ext-nacl)# 60 permit tcp any 192.168.10.0 0.0.0.255 established

! Everything else denied (implicit deny)
R1(config-ext-nacl)# exit

! Apply close to source
R1(config)# interface gi0/0                               ! LAN-facing interface
R1(config-if)# ip access-group INTERNET-FILTER in        ! Inbound from LAN

! ===== PROTECT VTY LINES with ACL =====
R1(config)# ip access-list standard SSH-ONLY
R1(config-std-nacl)# permit 192.168.1.0 0.0.0.255        ! Only management subnet
R1(config-std-nacl)# exit

R1(config)# line vty 0 15
R1(config-line)# access-class SSH-ONLY in                ! ACL on VTY lines

5.3 Editing and Verifying ACLs

! ===== ADD A RULE (named ACL — insert by sequence number) =====
R1(config)# ip access-list extended INTERNET-FILTER
R1(config-ext-nacl)# 15 permit tcp 192.168.20.0 0.0.0.255 any eq 80  ! Inserts between 10 and 20

! ===== DELETE A RULE =====
R1(config)# ip access-list extended INTERNET-FILTER
R1(config-ext-nacl)# no 30                               ! Remove sequence 30

! ===== DELETE ENTIRE ACL =====
R1(config)# no ip access-list extended INTERNET-FILTER

! ===== RENUMBER SEQUENCES =====
R1(config)# ip access-list resequence INTERNET-FILTER 10 10  ! Start at 10, increment by 10

! ===== VERIFICATION =====
R1# show access-lists                                    ! All ACLs with hit counts
R1# show access-lists INTERNET-FILTER                    ! Specific ACL
R1# show ip interface gi0/0                             ! Which ACLs applied to interface
R1# show running-config | section access-list            ! ACLs in config
R1# clear ip access-list counters                       ! Reset hit counters
ACL hit counts are your best friend for troubleshooting. After applying an ACL, generate test traffic and run show access-lists. Each statement shows how many packets matched. If a permit rule shows 0 hits but traffic should be flowing — either the traffic isn't reaching the router, or a deny rule above it is matching first. Always check the order.

6. NAT for IPv4 Module 6 Lab Heavy

6.1 NAT Concepts

TermDefinition
Inside LocalPrivate IP of internal host as seen from inside — e.g., 192.168.1.10
Inside GlobalPublic IP of internal host as seen from outside — the translated address
Outside LocalIP of external host as seen from inside network
Outside GlobalActual public IP of external host — usually same as Outside Local
Static NATOne-to-one permanent mapping — inside local ↔ inside global
Dynamic NATMaps inside locals to a pool of public IPs — one-to-one but dynamic
PAT (NAT Overload)Many-to-one — multiple private IPs share ONE public IP using port numbers

6.2 Static NAT Configuration

! Static NAT — one internal server always gets same public IP
! Example: web server at 192.168.1.10 always appears as 203.0.113.10

R1(config)# ip nat inside source static 192.168.1.10 203.0.113.10

! Mark inside and outside interfaces
R1(config)# interface gi0/0                             ! LAN interface
R1(config-if)# ip nat inside

R1(config)# interface gi0/1                             ! WAN/ISP interface
R1(config-if)# ip nat outside

6.3 Dynamic NAT Configuration

! Define the pool of public IPs
R1(config)# ip nat pool PUBLIC-POOL 203.0.113.1 203.0.113.10 netmask 255.255.255.240

! Define which inside addresses get translated (standard ACL)
R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255

! Link ACL to pool
R1(config)# ip nat inside source list 1 pool PUBLIC-POOL

! Mark interfaces
R1(config)# interface gi0/0
R1(config-if)# ip nat inside
R1(config)# interface gi0/1
R1(config-if)# ip nat outside

6.4 PAT (NAT Overload) — Most Common

! PAT using the router's WAN interface IP (most common — single public IP)
R1(config)# access-list 1 permit 192.168.0.0 0.0.255.255   ! All private traffic

R1(config)# ip nat inside source list 1 interface gi0/1 overload   ! Key: overload keyword

R1(config)# interface gi0/0
R1(config-if)# ip nat inside
R1(config)# interface gi0/1
R1(config-if)# ip nat outside

! PAT using a pool (when you have multiple public IPs)
R1(config)# ip nat inside source list 1 pool PUBLIC-POOL overload

! ===== VERIFICATION =====
R1# show ip nat translations                ! NAT table — inside local/global mappings
R1# show ip nat translations verbose        ! Detailed with timers
R1# show ip nat statistics                  ! Hit counts, active translations
R1# clear ip nat translation *              ! Clear all dynamic NAT entries
R1# debug ip nat                            ! Watch NAT translations in real time

9. QoS Concepts Module 9

9.1 Why QoS?

Networks experience congestion when more traffic arrives than can be forwarded. Without QoS, all traffic is treated equally — a large file download competes equally with a VoIP call. VoIP loses. QoS prioritizes time-sensitive traffic so voice and video get guaranteed bandwidth and low latency.

9.2 QoS Characteristics

CharacteristicDefinitionAffects
BandwidthRate of data transfer (bps)Throughput — how much data can flow
Delay (Latency)Time for packet to travel source to destinationVoIP quality — should be <150ms one-way
JitterVariation in delay between packetsVoIP/video — causes choppy audio
Packet LossPackets dropped due to congestionVoIP — should be <1%, video <5%

DiffServTraffic classified and marked — each class gets different treatmentEnterprise standard — scalable

11. Network Design Module 11

11.1 Hierarchical Network Design

LayerRoleDevicesKey Features
AccessConnect end devices to networkAccess switches, WAPsPort security, VLANs, PoE, STP PortFast
DistributionAggregate access layer, policy enforcementL3 switches, routersInter-VLAN routing, ACLs, QoS, redundancy
CoreHigh-speed backbone — move traffic fastHigh-speed L3 switches/routersSpeed, redundancy, no complex policy — just forward fast

11.2 Scalable Network Design Principles

  • Redundancy: Eliminate single points of failure — dual links, dual devices
  • Modularity: Build in blocks — easier to expand and troubleshoot
  • Resiliency: Network continues operating despite failures
  • Flexibility: Support future growth without redesign
  • Manageability: Consistent naming, addressing, and documentation

11.3 Switched Network Design Considerations

  • Collision domain: Each switch port is its own collision domain — full duplex eliminates collisions
  • Broadcast domain: One VLAN = one broadcast domain — route between VLANs
  • MAC table size: Large switches support 100,000+ MAC entries
  • Port density: Number of ports per switch — affects cabling and rack space
  • PoE budget: Total watts available for powered devices — WAPs + IP phones

12.2 OSPF Troubleshooting

! OSPF neighbors won't form — check these:
R1# show ip ospf neighbor                    ! State should be FULL (or 2-WAY for DROther)
R1# show ip ospf interface gi0/1            ! Hello/Dead timers, area, DR/BDR

! Common OSPF problems:
! 1. Different area numbers
! 2. Hello/Dead timer mismatch
! 3. MTU mismatch (stuck in EXSTART/EXCHANGE)
! 4. Passive-interface on wrong interface
! 5. ACL blocking OSPF multicast (224.0.0.5 and 224.0.0.6)
! 6. Different network types (point-to-point vs broadcast)
! 7. Authentication mismatch

! Fix MTU mismatch
R1(config)# interface gi0/1
R1(config-if)# ip ospf mtu-ignore           ! Ignore MTU during adjacency

! Check if ACL blocking OSPF
R1# show ip access-lists                    ! Look for hits on permit/deny for OSPF traffic

12.3 ACL Troubleshooting

! ACLs blocking unexpected traffic — systematic checks:

! 1. What ACLs are applied where?
R1# show ip interface                        ! Shows inbound/outbound ACL per interface

! 2. What does the ACL actually say?
R1# show access-lists ACL-NAME              ! With hit counts

! 3. Reset counters, generate test traffic, check counts
R1# clear ip access-list counters
! [generate traffic]
R1# show access-lists                        ! Which rules got hits?

! 4. Common mistakes:
!    - Wrong direction (in vs out)
!    - Wrong interface
!    - Too permissive or too restrictive
!    - Missing permit for return traffic
!    - Implicit deny blocking needed traffic

! TEMPORARY: Add permit any to test (REMOVE after!)
R1(config)# ip access-list extended TEST-ACL
R1(config-ext-nacl)# 999 permit ip any any  ! Temp — if traffic flows now, ACL is the problem

12.4 NAT Troubleshooting

! NAT not translating — check these:

! 1. Is the translation happening?
R1# show ip nat translations                ! Is there an entry for the source IP?

! 2. Are interfaces marked correctly?
R1# show ip nat statistics                  ! Shows inside/outside interfaces

! 3. Is the ACL matching traffic?
R1# show access-lists                       ! Is the permit ACL getting hits?

! 4. Test from inside
R1# ping 8.8.8.8 source 192.168.1.10       ! Ping from inside IP

! Common NAT mistakes:
! - Wrong interface marked inside/outside
! - ACL too restrictive — not matching inside traffic
! - Pool exhausted (dynamic NAT)
! - Missing overload keyword (PAT)
! - Routing issue — traffic not reaching NAT router

13.2 Virtual Network Infrastructure

  • vSwitch (Virtual Switch): Software switch inside a hypervisor — connects VMs to each other and to physical NICs
  • vNIC: Virtual Network Interface Card — assigned to each VM
  • Distributed vSwitch (DVS): VMware feature — single vSwitch spanning multiple ESXi hosts, managed centrally
  • NSX: VMware's network virtualization platform — full Layer 2–7 networking in software
  • VXLAN: Virtual Extensible LAN — extends Layer 2 over Layer 3 using UDP encapsulation (24-bit VNID = 16M segments vs 4096 VLANs)

  • Northbound API: Between controller and applications (REST API)
  • Southbound API: Between controller and network devices (OpenFlow, NETCONF, RESTCONF)
  • Benefit: Centralized management, programmable, vendor-agnostic (open standards)

14. Network Automation Module 14

14.1 Why Network Automation?

  • Manual CLI config doesn't scale — 1000 switches × 50 commands = errors and inconsistency
  • Automation = consistent, repeatable, fast, auditable changes
  • Reduces human error — the #1 cause of network outages
  • Enables Infrastructure as Code (IaC) — network config in version control

14.3 APIs

  • REST API: Uses HTTP methods — GET (read), POST (create), PUT (update), DELETE (remove)
  • NETCONF: Network Configuration Protocol — uses XML over SSH, RFC 6241

14.5 Simple Python Network Automation Example

# Using Netmiko to configure multiple routers
from netmiko import ConnectHandler

device = {
    'device_type': 'cisco_ios',
    'host': '192.168.1.1',
    'username': 'admin',
    'password': 'Cisco123!',
    'secret': 'class',           # Enable password
}

commands = [
    'interface loopback 0',
    'ip address 1.1.1.1 255.255.255.255',
    'no shutdown',
    'description Loopback for OSPF RID',
]

# Connect and send commands
with ConnectHandler(**device) as net_connect:
    net_connect.enable()         # Enter privileged EXEC
    output = net_connect.send_config_set(commands)
    net_connect.save_config()    # copy run start
    print(output)
