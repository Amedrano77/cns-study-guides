1. Virtualization Fundamentals

1.1 What is Virtualization?

Virtualization is the process of creating a software-based (virtual) version of a physical resource — a computer, server, storage device, or network. Instead of one server running one operating system doing one job, virtualization lets one physical machine run multiple virtual machines simultaneously, each with their own OS, resources, and applications.

1.2 Key Virtualization Terminology

HostThe physical machine running the hypervisor
Guest / VMThe virtual machine running on top of the hypervisor
HypervisorSoftware layer that creates and manages virtual machines

vRAMVirtual RAM — memory allocated to a VM from host's physical RAM

2. CPU Virtualization & SLAT Lab 1

2.1 How CPU Virtualization Works

Modern CPUs have hardware-level virtualization extensions that allow a hypervisor to run guest OSes with near-native performance. Without hardware support, every privileged CPU instruction from a guest OS would need to be trapped and emulated — extremely slow. With hardware virtualization, the CPU handles this directly.

FeatureIntel NameAMD NameWhat It Does
Hardware VirtualizationVT-x (VMX)AMD-V (SVM)Allows hypervisor to run guest VMs with hardware acceleration
SLATEPT (Extended Page Tables)RVI (Rapid Virtualization Indexing)Allows nested page table mapping — speeds up memory access in VMs significantly
I/O VirtualizationVT-dAMD-Vi / IOMMUAllows VMs to directly access physical hardware (PCIe passthrough)

2.2 SLAT — Second Level Address Translation

  • Without SLAT: Guest OS manages virtual→physical memory translations, hypervisor must intercept each one — very slow
  • With SLAT (EPT/RVI): CPU handles two levels of address translation in hardware — guest virtual → guest physical → host physical — without hypervisor intervention
  • Result: Much better VM performance, especially for memory-intensive workloads
  • Required for: Proxmox VE, VMware ESXi, Hyper-V, nested virtualization
  • Check for SLAT: System Information → Hyper-V Second Level Address Translation Extensions: Yes

2.3 Virtualization-Based Security (VBS)

  • Windows 11 feature that uses Hyper-V to create an isolated secure region of memory
  • Protects Windows kernel from malware — but conflicts with other hypervisors
  • When VBS is active, Hyper-V claims the hardware virtualization extensions — other hypervisors (Proxmox, VMware, VirtualBox) can't use them
  • Must be disabled on Windows hosts when running Proxmox nested VMs or VMware Workstation
🧪 Lab 1 — Enabling SLAT & Disabling VBS on Windows 11

In this lab you will configure your Windows 11 system to enable Second Level Address Translation (SLAT) for nested virtualization. Intel calls their implementation Extended Page Tables (EPT); AMD calls theirs Rapid Virtualization Indexing (RVI). The goal: disable Windows features that block nested virtualization so we can run VMs inside VMs.

⚠️ Not every system is the same. Most Windows 11 machines only need the steps below, but as Windows adds new features, additional steps may be necessary.

Step 1 — Disable Hyper-V and Related Features

  1. Open the Windows Start Menu
  2. Search for "Features"
  3. Select "Turn Windows features on or off"
  4. Find and uncheck "Hyper-V"
  5. Find and uncheck "Virtual Machine Platform"
  6. Find and uncheck "Windows Hypervisor Platform"
  7. Click OK and allow Windows to make changes

Step 2 — Disable Memory Integrity

  1. Open the Windows Start Menu
  2. Search for "Core"
  3. Select "Core Isolation"
  4. Find Memory Integrity and the toggle below it
  5. Flip the toggle to the Off position
  6. Reboot Windows

Step 3 — Verify VBS is Disabled and SLAT is Enabled

  1. Open the Windows Start Menu
  2. Type "sysinfo"
  3. Select the "System Information" app
  4. Select "System Summary" in the left column
  5. In the right column, find Virtualization-based security — verify it shows "Not enabled"
  6. In the right column, find Hyper-V - Second Level Address Translation Extensions — verify it shows "Yes"
🛑 If Virtualization-based Security is "Not enabled" AND Second Level Address Translation Extensions is "Yes" — you are ready to proceed. If either is incorrectly set, contact your instructor before continuing.

🧪 Lab 2 — Installing Proxmox VE

Step 1 — Download Proxmox ISO

  1. Go to proxmox.com/downloads
  2. Download the latest Proxmox VE ISO Installer
  3. Flash to USB using Rufus (Windows) or Etcher (cross-platform)

  1. Boot into BIOS/UEFI (usually F2, F10, or DEL on startup)
  2. Enable Intel VT-x or AMD-V (CPU Virtualization)
  3. Enable VT-d or AMD IOMMU (for PCIe passthrough)
  4. Set boot order: USB first
  5. Save and reboot

Step 3 — Install Proxmox VE

  1. Boot from USB — select "Install Proxmox VE (Graphical)"
  2. Accept the EULA
  3. Select target hard disk — this will be wiped!
  4. Set country, timezone, keyboard layout
  5. Set root password and email address
  6. Configure network: hostname (e.g. pve.tstc.local), IP address, gateway, DNS
  7. Review summary — click Install
  8. Remove USB when prompted, system reboots

Step 4 — Access the Web Interface

  1. From another machine, open a browser
  2. Navigate to https://[your-proxmox-IP]:8006
  3. Accept the self-signed certificate warning
  4. Login: username root, password you set during install, realm Linux PAM
  5. Dismiss the "No valid subscription" notice — click OK
⚠️ Always use a static IP for your Proxmox host. If the IP changes, you lose access to the web UI and all VMs lose their network paths.

7. Creating Virtual Machines Lab 3 Proxmox

7.1 VM Creation Wizard — Step by Step

🧪 Lab 3 — Creating Your First VM in Proxmox

Step 1 — Upload ISO to Proxmox

  1. In the left tree, click your node → local storage
  2. Click ISO Images tab
  3. Click Upload to upload from your computer, OR click Download from URL to pull directly (paste the ISO URL)

Step 2 — Create VM

  1. Click "Create VM" in the top right
  2. General: Set Node, VMID (auto), Name (e.g. ubuntu-server), click Next
  3. OS: Select ISO image from local storage, set Guest OS type (Linux/Windows/Other), click Next
  4. System: Leave defaults for most VMs. For Windows: enable Qemu Agent. Click Next
  5. Disks: Set storage (local-lvm), disk size (e.g. 32GB), Bus (VirtIO SCSI for Linux, SATA for Windows). Click Next
  6. CPU: Set number of sockets and cores. Enable host CPU type for best performance. Click Next
  7. Memory: Set RAM in MB (2048 = 2GB, 4096 = 4GB). Click Next
  8. Network: Select bridge (vmbr0), model (VirtIO for Linux, E1000 for Windows until drivers installed). Click Next
  9. Confirm: Review settings, check "Start after created" if ready, click Finish

Step 3 — Install the OS

  1. Click the VM in the left tree
  2. Click the Console tab — you'll see the VM's screen
  3. Click Start if VM isn't running
  4. Complete the OS installation normally as if it were a physical machine
  5. After installation, go to Hardware → CD/DVD Drive → set to "Do not use any media" to remove the ISO
⚠️ Always install the QEMU Guest Agent after OS installation. It allows Proxmox to communicate with the VM — enables clean shutdowns, IP reporting, and freeze-consistent snapshots.

9.2 Common Network Configurations

# ===== /etc/network/interfaces — Proxmox network config =====

# Single NIC — Management + VMs on same bridge
auto lo
iface lo inet loopback

auto eno1
iface eno1 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
    bridge-ports eno1
    bridge-stp off
    bridge-fd 0
    dns-nameservers 192.168.1.1

# ===== TWO NIC SETUP — Management separate from VM traffic =====
# eno1 = Management network
auto eno1
iface eno1 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1

# eno2 = VM traffic bridge (no IP — VMs get their own IPs)
auto eno2
iface eno2 inet manual

auto vmbr1
iface vmbr1 inet manual
    bridge-ports eno2
    bridge-stp off
    bridge-fd 0

# ===== VLAN-AWARE BRIDGE =====
auto vmbr0
iface vmbr0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
    bridge-ports eno1
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes       ! Enables VLAN tagging per VM port

10.2 Creating an LXC Container

# ===== DOWNLOAD CONTAINER TEMPLATE =====
# In Web UI: Node → local storage → CT Templates → Templates button → search and download
# OR via CLI:
pveam update                                        # Update template list
pveam available                                     # List available templates
pveam download local debian-12-standard_12.7-1_amd64.tar.zst  # Download Debian 12

# ===== CREATE CONTAINER VIA CLI =====
pct create 200 local:vztmpl/debian-12-standard_12.7-1_amd64.tar.zst \
    --hostname webserver \
    --memory 512 \
    --cores 1 \
    --net0 name=eth0,bridge=vmbr0,ip=192.168.1.50/24,gw=192.168.1.1 \
    --storage local-lvm \
    --rootfs local-lvm:8 \
    --password YourRootPass \
    --unprivileged 1                                # Unprivileged = safer

# ===== START / STOP / STATUS =====
pct start 200
pct stop 200
pct status 200
pct list                                            # List all containers

# ===== ENTER CONTAINER SHELL =====
pct enter 200                                       # Drop into container shell
pct exec 200 -- bash                               # Run bash in container
Use unprivileged containers whenever possible. Unprivileged containers run with a mapped UID/GID range — root inside the container is NOT root on the host. This dramatically limits what an attacker can do if they escape the container. Only use privileged containers when you specifically need hardware access (like USB passthrough or specific kernel features).

11. Snapshots, Backups & Templates Lab 5 Proxmox

11.1 Snapshots

  • A snapshot captures the entire state of a VM at a point in time — disk, RAM, and config
  • Instant to create — stored as metadata + delta from current disk state
  • Use before: OS updates, software installs, config changes, student labs
  • Requires qcow2 disk format or ZFS/LVM-Thin storage (raw format on LVM doesn't support snapshots)
  • Too many snapshots = performance degradation — snapshots are not backups!
# ===== SNAPSHOT VIA CLI =====
qm snapshot 101 snap-before-update --description "Before apt upgrade" --vmstate
# --vmstate includes RAM state (can resume exactly where left off)

# ===== LIST SNAPSHOTS =====
qm listsnapshot 101

# ===== ROLLBACK TO SNAPSHOT =====
qm rollback 101 snap-before-update

# ===== DELETE SNAPSHOT =====
qm delsnapshot 101 snap-before-update

# ===== CONTAINERS =====
pct snapshot 200 snap1 --description "Clean Debian install"
pct rollback 200 snap1

11.2 Backups

# ===== MANUAL BACKUP VIA CLI =====
vzdump 101 --storage local --mode snapshot --compress zstd
# Modes: snapshot (fastest, requires storage support), suspend, stop (safest)
# Compress: zstd (fast+good), gzip, lzo, none

# ===== SCHEDULED BACKUPS (Web UI) =====
# Datacenter → Backup → Add
# Set schedule (cron-style), storage, VMs to include, retention policy

# ===== RESTORE FROM BACKUP =====
# Web UI: local storage → Backups → select file → Restore
# OR CLI:
qmrestore /var/lib/vz/dump/vzdump-qemu-101-2024_01_15.vma.zst 101 --storage local-lvm

11.3 VM Templates

# Templates let you rapidly clone identical VMs — perfect for lab deployments

Need to reset a lab? Delete the clone and re-clone from the template. This is how you run 20-student labs on one Proxmox server without losing your mind.

12. Proxmox Clustering & High Availability Proxmox

12.1 Proxmox Cluster Concepts

  • A Proxmox cluster groups multiple physical hosts into one management unit
  • Manage all nodes from any node's web UI
  • Enables live migration — move running VMs between nodes with no downtime
  • Enables HA (High Availability) — if a node fails, its VMs restart on surviving nodes
  • Minimum 3 nodes for quorum — prevents split-brain (2 nodes can't agree who's in charge)
  • Uses Corosync for cluster communication — needs low-latency dedicated link

12.2 Creating a Cluster

# ===== ON THE FIRST NODE (will be cluster master) =====

# ===== ON ADDITIONAL NODES (join existing cluster) =====
pvecm add 192.168.1.10          # IP of first node

# ===== VERIFY CLUSTER STATUS =====
pvecm status                    # Cluster health, quorum, nodes
pvecm nodes                     # List all nodes

# ===== LIVE MIGRATE VM TO ANOTHER NODE =====
qm migrate 101 pve2             # Migrate VM 101 to node "pve2"
qm migrate 101 pve2 --online    # Live migration — VM keeps running

13. Nested Virtualization Lab 6 Proxmox

13.1 What is Nested Virtualization?

Nested virtualization allows you to run a hypervisor inside a VM — a VM running inside Proxmox that can itself run VMs. This is how you build entire virtual lab environments on a single physical machine — one Proxmox host running student VMs, each of which can run their own virtual network.

13.2 Enable Nested Virtualization in Proxmox

# ===== CHECK IF NESTED VIRT IS ALREADY ENABLED =====
# Intel:
cat /sys/module/kvm_intel/parameters/nested    # Should show "Y" or "1"
# AMD:
cat /sys/module/kvm_amd/parameters/nested      # Should show "Y" or "1"

# ===== ENABLE PERMANENTLY =====
# Intel:
echo "options kvm-intel nested=Y" > /etc/modprobe.d/kvm-intel.conf
# AMD:
echo "options kvm-amd nested=1" > /etc/modprobe.d/kvm-amd.conf

# Reload module
modprobe -r kvm_intel && modprobe kvm_intel      # Intel
modprobe -r kvm_amd && modprobe kvm_amd          # AMD

# ===== SET VM CPU TYPE TO "host" =====
# In Web UI: VM → Hardware → Processors → Type: host
# OR CLI:
qm set 101 --cpu host
🧪 Lab 6 — Configuring Nested Virtualization

In this lab you will configure both the Proxmox host AND your Windows client to enable nested virtualization — the ability to run VMs inside VMs.

On the Proxmox Host:

  1. SSH into your Proxmox node or open the Shell in the web UI
  2. Check your CPU vendor: grep -m1 vendor_id /proc/cpuinfo
  3. For Intel: run echo "options kvm-intel nested=Y" > /etc/modprobe.d/kvm-intel.conf
  4. For AMD: run echo "options kvm-amd nested=1" > /etc/modprobe.d/kvm-amd.conf
  5. Reload the module (or reboot)
  6. Set the VM's CPU type to host in VM Hardware settings

On the Windows 11 Client (for running Proxmox in a VM):

  1. Follow Lab 1 steps to disable Hyper-V, VMP, and Windows Hypervisor Platform
  2. Disable Memory Integrity in Core Isolation
  3. Reboot and verify in System Information: VBS = "Not enabled", SLAT = "Yes"
⚠️ Nested virtualization has a performance cost — each layer adds overhead. For production workloads, always run on bare metal. For labs, nested is perfectly acceptable.
