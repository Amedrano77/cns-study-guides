1.2 Server CPU Concepts

  • Multi-socket: Servers can have 2, 4, or more physical CPU sockets — scales processing power
  • NUMA (Non-Uniform Memory Access): Each CPU has its own memory bank — accessing local memory faster than remote
  • Hyperthreading (Intel) / SMT (AMD): Each physical core appears as 2 logical cores to the OS
  • Server CPUs: Intel Xeon, AMD EPYC — higher core counts, ECC memory support, more PCIe lanes than desktop CPUs
  • TDP (Thermal Design Power): Max heat output — determines cooling requirements

1.3 Server RAM

TypeDescriptionServer Use

1.4 Power & Cooling

  • Redundant PSUs: Two or more power supplies — if one fails, others continue (1+1 or 2+1)
  • Hot-swap PSU: Replace failed power supply without powering down server
  • 80 PLUS rating: PSU efficiency — Titanium (96%) is highest, Bronze (82%) is minimum acceptable
  • Hot/Cold Aisle: Server racks face alternating directions — cold air intakes on one side, hot exhaust on other
  • CRAC (Computer Room Air Conditioning): Dedicated precision cooling for server rooms
  • PUE (Power Usage Effectiveness): Total facility power / IT equipment power. PUE of 1.0 = perfect, typical datacenter = 1.5–2.0

RAID is NOT a backup. RAID protects against disk failure — it does NOT protect against accidental deletion, ransomware, file corruption, or theft. A RAID array can mirror corrupt data just as faithfully as good data. Always have a separate backup strategy in addition to RAID.

5. Server Networking Domain 1

5.1 NIC Teaming / Bonding

  • Combine multiple physical NICs into one logical interface — redundancy and/or increased bandwidth
  • Active-Passive (mode 1): One NIC active, other standby — failover only, no bandwidth increase
  • Active-Active / LACP (mode 4): Both NICs active, load balanced — requires switch support (802.3ad)
  • Round-Robin (mode 0): Transmit on each NIC in turn — simple load balancing, no switch config needed
# ===== LINUX NIC BONDING =====
# Install bonding tools
apt install ifenslave -y

# Create bond interface
nmcli con add type bond con-name bond0 ifname bond0 bond.options "mode=active-backup"
nmcli con add type ethernet con-name bond0-slave1 ifname ens3 master bond0
nmcli con add type ethernet con-name bond0-slave2 ifname ens4 master bond0

# Verify
cat /proc/net/bonding/bond0          # Bond status and active interface

5.2 Server Network Best Practices

  • Separate management NIC: Dedicated NIC for iDRAC/iLO management — never share with production traffic
  • Separate storage NIC: Dedicated NICs for iSCSI or NFS — avoid contention with application traffic
  • Jumbo frames: MTU 9000 for storage networks — reduces CPU overhead for large transfers
  • Flow control: Enable on storage NICs — prevents packet loss during bursts
  • Static IPs for servers: Never use DHCP on production servers — create DNS reservations instead

# ===== KEY FILES =====

/etc/nginx/sites-available/        # Server block configs
/etc/nginx/sites-enabled/          # Symlinks to active configs
/etc/nginx/conf.d/                 # Additional configs (RHEL)
/var/www/html/                     # Default document root
/var/log/nginx/access.log
/var/log/nginx/error.log

# ===== SERVER BLOCK (Virtual Host) =====
sudo nano /etc/nginx/sites-available/mysite
server {
    listen 80;
    listen [::]:80;
    server_name mysite.tstc.edu www.mysite.tstc.edu;
    root /var/www/mysite;
    index index.html index.htm index.php;

    location / {
        try_files $uri $uri/ =404;
    }

    # PHP-FPM support
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
    }

    # Deny .htaccess access
    location ~ /\.ht {
        deny all;
    }

    access_log /var/log/nginx/mysite_access.log;
    error_log  /var/log/nginx/mysite_error.log;
}
# Enable site
sudo ln -s /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/
sudo nginx -t                      # Test config syntax
sudo systemctl reload nginx        # Apply changes

# ===== NGINX AS REVERSE PROXY =====
# In server block:
location / {

    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_cache_bypass $http_upgrade;

7.2 BIND DNS Server Configuration

# ===== INSTALL BIND9 =====
sudo apt install bind9 bind9utils bind9-doc -y

# ===== KEY FILES =====
/etc/bind/named.conf               # Main config
/etc/bind/named.conf.options       # Global options
/etc/bind/named.conf.local         # Zone declarations
/var/cache/bind/                   # Zone data files
/var/log/named/                    # DNS logs

# ===== named.conf.options =====
sudo nano /etc/bind/named.conf.options
options {
    directory "/var/cache/bind";

    // Allow queries from local network only
    allow-query { localhost; 192.168.1.0/24; };

    // Forward unknown queries to public DNS
    forwarders {
        8.8.8.8;
        8.8.4.4;
    };
    forward only;

    // DNSSEC validation
    dnssec-validation auto;

    listen-on { any; };
    listen-on-v6 { any; };
};
# ===== named.conf.local — declare zones =====
zone "tstc.edu" {
    type master;
    file "/var/cache/bind/db.tstc.edu";
    allow-transfer { 192.168.1.11; };   # Secondary DNS server
};

zone "1.168.192.in-addr.arpa" {
    type master;
    file "/var/cache/bind/db.192.168.1";
};
# ===== FORWARD ZONE FILE: /var/cache/bind/db.tstc.edu =====
$TTL 86400
@   IN  SOA ns1.tstc.edu. admin.tstc.edu. (
            2024011501  ; Serial (YYYYMMDDnn)
            3600        ; Refresh
            1800        ; Retry
            604800      ; Expire
            86400 )     ; Negative TTL

; Name servers
@       IN  NS  ns1.tstc.edu.
@       IN  NS  ns2.tstc.edu.

; A records
ns1     IN  A   192.168.1.10
ns2     IN  A   192.168.1.11
www     IN  A   192.168.1.20
mail    IN  A   192.168.1.30
ftp     IN  A   192.168.1.40

; CNAME
webmail IN  CNAME  mail

; MX record
@       IN  MX  10  mail.tstc.edu.

; TXT (SPF)
@       IN  TXT "v=spf1 mx ~all"
# Verify zone file syntax
sudo named-checkzone tstc.edu /var/cache/bind/db.tstc.edu
sudo named-checkconf                   # Check all config files

# Restart and test
sudo systemctl restart bind9
dig @192.168.1.10 www.tstc.edu         # Test from specific DNS server
nslookup www.tstc.edu 192.168.1.10    # Alternative test

10.2 Email Authentication Records

RecordTypePurposeExample
SPFTXTSpecifies which mail servers are authorized to send for a domainv=spf1 mx include:sendgrid.net ~all
DKIMTXTDigitally signs outgoing email — receiver verifies signatureselector._domainkey TXT "v=DKIM1; k=rsa; p=MIGf..."
DMARCTXTPolicy for what to do when SPF/DKIM fail — reject, quarantine, or nonev=DMARC1; p=quarantine; rua=mailto:dmarc@tstc.edu
SPF + DKIM + DMARC together = email authentication trifecta. Without them, anyone can forge your domain in the From: field. SPF says who's allowed to send. DKIM proves the message wasn't tampered with. DMARC tells receiving servers what to DO when SPF or DKIM fails. All three are required for professional email delivery — without them your mail goes to spam.

12.3 Manual Self-Signed Certificate

# Generate CSR
openssl req -new -key server.key -out server.csr

# Self-sign (for internal/lab use only)
openssl x509 -req -days 365 -in server.csr -signkey server.key -out server.crt

# View certificate details
openssl x509 -in server.crt -text -noout

# Test SSL/TLS connection

    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
}

14.2 Linux Backup Tools

# ===== AUTOMATED BACKUP SCRIPT =====
#!/bin/bash
BACKUP_DIR="/backup"
DATE=$(date +%Y%m%d_%H%M%S)
LOG="/var/log/backup.log"

echo "$(date) - Starting backup" >> $LOG

# Backup web files
tar -czf $BACKUP_DIR/www_$DATE.tar.gz /var/www 2>> $LOG

# Backup databases
mysqldump --all-databases -u root -p"$MYSQL_PASS" | \
    gzip > $BACKUP_DIR/mysql_$DATE.sql.gz 2>> $LOG

# Keep only last 7 days
find $BACKUP_DIR -name "*.tar.gz" -mtime +7 -delete
find $BACKUP_DIR -name "*.sql.gz" -mtime +7 -delete

echo "$(date) - Backup complete" >> $LOG

# Add to crontab: 0 2 * * * /usr/local/bin/backup.sh

16. Troubleshooting Servers Domain 5

16.1 Server Troubleshooting Methodology

  1. Identify the problem — What exactly is failing? Error message? Which service? Since when?
  2. Check service status — Is the service running? Any errors in status output?
  3. Check logs — Always check logs first — they tell you exactly what went wrong
  4. Check resources — Is the disk full? Out of RAM? CPU pegged?
  5. Check network — Is the port listening? Firewall blocking? DNS resolving?
  6. Test connectivity — Can you reach the service locally? Remotely?
  7. Fix and verify — Apply fix, confirm service works, watch logs
  8. Document — Write it down for next time

16.2 Quick Troubleshooting Reference

16.3 The Most Useful Troubleshooting One-Liners

# What is listening on port 80?
ss -tlpn | grep :80
lsof -i :80

# What changed in the last hour?
find /etc -newer /tmp/ref_time -type f 2>/dev/null
journalctl --since "1 hour ago" --priority=err

# Test if web server is responding
curl -I http://localhost                        # HTTP headers only
curl -vk https://localhost                      # Verbose HTTPS test
wget -qO- http://localhost | head -20           # First 20 lines of response

# Check certificate expiry
echo | openssl s_client -connect mysite.tstc.edu:443 2>/dev/null | \
    openssl x509 -noout -dates

# Test DNS from a specific server
dig @8.8.8.8 mysite.tstc.edu
nslookup mysite.tstc.edu 192.168.1.10

# Find which process opened a file
lsof /var/log/nginx/error.log
lsof -p 1234                                   # All files opened by PID 1234

# Test SMTP server
telnet mail.tstc.edu 25
# Type: EHLO test.com → MAIL FROM: → RCPT TO:

# Check if remote port is open
nc -zv 192.168.1.10 443
timeout 5 bash -c 'cat < /dev/null > /dev/tcp/192.168.1.10/443' && echo "OPEN"
Check the logs before you do anything else. 90% of server problems announce themselves in the logs with the exact error and line number. journalctl -xe for systemd services, tail -f /var/log/nginx/error.log for web, /var/log/auth.log for SSH.
